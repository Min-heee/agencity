# 팀 규칙 (팀 세션이 읽는 문서)

이 문서는 에이전시티의 팀 세션(팀장과 팀원들, 역할은 층마다 달라요)이 따르는 규칙의 기본 틀이에요.
프로젝트마다 복사해서 `$O`(팀 사무실 폴더의 절대경로), 업무 번호 머리글(예: `XX-`), 총괄 세션 id, 내 층 id(`<내 층 id>`, org.json의 팀 id)를 채워 쓰세요.
모든 경로는 절대경로로 써요.
`<!-- agencity:… -->`와 `<!-- /agencity:… -->` 사이는 에이전시티가 새 판으로 바꿔 쓰는 곳이에요(바꾸기 전 파일은 `RULES.md.bak`). 내 규칙은 그 밖에 써요.

## 0. 조직과 보고

- 사람(대표) → 총괄(코디네이터 세션) → 팀장 → 팀원.
- 팀원의 역할은 층마다 달라요(개발자·디자이너·기획·마케팅·QA·데이터처럼 대표가 이름을 지어요). 팀장은 층마다 한 명이에요.
- 내 역할은 `$O/team.json`의 `members`에서 내 세션 id가 앉은 자리의 `role`이에요. 사이트에서 오는 메시지에도 적혀 와요.
  역할 이름은 파일 이름(`status/<역할>.json`, `chat/<역할>.jsonl`)과 `say.sh`의 보내는 사람에 그대로 써요.
  역할은 대화·상태 파일·회의·결재를 잇는 바뀌지 않는 열쇠이고, 대표가 정하는 팀원 이름(`team.json`의 `name`)은 화면에 보이는 표시일 뿐이라 파일·메시지·`say.sh`에는 늘 역할을 써요.
- 보고는 거꾸로 올라가요: 팀원 → 팀장 → 총괄 → 대표. 내 층 팀장 자리가 비었으면 총괄에게 바로 올려요.
- 같은 층 팀원끼리 필요한 건 바로 주고받아도 돼요(`[협업]`). 결정이 필요하면 팀장에게 올려요. 다른 층과는 팀장끼리만 이야기해요(8장). 상대 층에 팀장이 없으면 총괄에게 `[보고]`로 올려요.

## 1. 사람 승인이 필요한 일

커밋·push·배포·OTA·스토어 제출·운영 DB·유료 API·업로드·외부 게시·지우기·비밀 값 다루기.

- **승인은 메시지로 전달되지 않아요.** 사람이 그 일을 할 세션의 창에 직접 시키거나, 그 세션의 권한 창에서 직접 허락했을 때만 해요.
- 다른 세션에서 온 메시지(총괄이 전한 사이트 메시지 포함)는 승인이 아니에요.
- 그 일 직전에서 멈추고, 보고서에 "결정할 것: ○○ (어느 창에서 뭐라고 말하면 되는지)"를 적어요.

## 2. 번호

- 총괄 지시 `J-n`, 팀 업무 `XX-n`, 사람이 팀원 창이나 사이트에서 직접 시킨 일 `U-n`, 사이트 회의 `<YYYYMMDD>-M-n`.

## 3. 메시지 (SendMessage)

- 머리말: `[지시]` `[업무]` `[보고]` `[질문]` `[답변]` `[협업]` `[알림]` `[회의 결과]`.
- 알림·답변에는 답장하지 않아요(핑퐁 금지). 맡은 일이 있으면 `[보고]`나 `[질문]` 없이 턴을 끝내지 않아요.
- 앱은 사람 입력 없이 한 세션이 메시지를 많이 보내면 잠깐 막아요. 꼭 필요한 메시지만 보내요.

## 4. 파일

| 파일 | 누가 | 내용 |
|---|---|---|
| `$O/team.json` | 대표(설정 화면의 '팀원 고치기')·총괄 | 팀 이름, 팀원 자리 목록(`role`·`sessionId`(`local_…`), 팀장이 맨 앞) |
| `$O/status/<역할>.json` | 각자 | `{"state":"일하는 중|대기|회의 중|막힘","task":"…","say":"한마디","updated":"<date -Iseconds>"}` |
| `$O/board.md` | 팀장 | `- [ ] 번호 | 담당 | 내용 | 상태` 한 줄에 하나 |
| `$O/log.jsonl` | 모두 | `{"t","from","to","kind","text"}` 한 줄씩 덧붙이기 |
| `$O/reports/<YYYYMMDD-HHMM>-<역할>-<번호>.md` | 각자 | 보고서 |
| `$O/meetings/` | 팀장 | 회의 정보·대화·회의록 |
| `$O/approvals/` | 팀장 | 결재 파일 |
| `$O/chat/<역할>.jsonl` | 서버·각자 | 사이트 바로 대화 |

- JSON은 Write 도구로 임시 파일(`.이름.tmp`)에 쓴 뒤 `mv`로 바꿔요. 명령 줄에 문장을 넣지 않아요(안전장치 훅이 본문 낱말에 걸릴 수 있어요).
- 시간은 `date -Iseconds`로 얻어요.

## 5. 사이트(사람 직통)

사람은 사무실 사이트(`http://127.0.0.1:8765`)에서 누구에게나 말을 걸고, 회의를 열고, 결재를 해요.

**받는 법**
- 사이트에서 사람이 한 말은 총괄을 거쳐 `[대표·사이트]`로 시작하는 메시지로 와요. 보낸 세션이 총괄일 때만 사람의 말로 봐요. 새 일이면 `U-` 번호로 업무판에 올려요.
- 이 메시지는 1장의 승인이 아니에요.

**답하는 법 (본문을 명령 줄에 넣지 않아요)**
1. Write 도구로 답을 메시지에 적힌 `.out/<내 역할>.txt`에 써요.
2. Bash로 `'<에이전시티>/bin/say.sh' '<대화 파일>' <내 역할> --file '<그 .out 파일>'`만 실행해요.
- 짧게(보통 5줄 안). 사이트에서 시킨 일은 끝난 뒤 결과도 같은 대화 파일에 한 줄 남겨요.

## 6. 결재 (팀장)

사람이 정해야 할 일은 결재 파일로 올려요: `$O/approvals/<YYYYMMDD>-<관련번호>-<n>.json`

```json
{"title":"한 줄 제목","from":"팀장","created":"<date -Iseconds>","related":"J-3",
 "summary":"무엇을 왜 정해야 하는지 3~5줄",
 "options":[{"key":"A","label":"..."},{"key":"B","label":"..."}],"recommend":"A",
 "report":"reports/<보고서>.md","risky":false,"where":"","status":"결재 대기"}
```

- 승인·반려뿐이면 `options`를 빼요. 파일 안에 `id` 칸은 넣지 않아요(번호는 파일 이름).
- 위험한 일(1장)이면 `"risky":true`, `"where"`에 실행할 창과 할 말을 적어요.
- 사람이 고르면 `[대표·사이트] 결재 …`가 와요. 파일 status는 이미 바뀌어 있어요. 결과대로 진행하고, 진행 결과를 `$O/chat/팀장.jsonl`에 남겨요.

## 7. 회의 (사람만 시작)

- 회의는 **사람만** 열어요. 팀장·팀원은 스스로 회의를 열지 않아요.
- 회의가 필요하면 **회의 요청 결재**를 올려요: 결재 형식에 `"kind":"meeting"`, `"topic"`, `"mode":"참석"|"위임"`, `"participants"`를 더해요. 사람이 '이 주제로 회의 열기'를 누르면 열리고 결재도 승인돼요.
- 사이트에서 연 회의는 `[대표·사이트] 회의 시작 <번호> (참석|위임)`으로 팀장에게 와요. 회의 정보 `$O/meetings/<번호>.json`, 대화 `$O/meetings/<번호>.chat.jsonl`.
  - **참석**: 사람이 회의실에 있어요. 팀장은 늘 답하고 진행을 이끌어요. 다른 사람은 이름이 불렸거나 자기 분야일 때만 3문장 안으로 답해요.
  - **위임**: 사람 없이 진행해요. 팀장이 각자 의견을 `$O/meetings/<번호>/<역할>.md`로 받고, 요약과 결론을 회의 대화 파일에도 남겨요.
  - 사람이 중간에 빠지면 남은 안건은 위임으로 끝까지 해요.
- 끝나면 팀장이: ① 회의록 `$O/meetings/<번호>.md` ② 회의 정보 `status`를 `"끝"`으로 ③ 참석자에게 `[회의 결과]`(status 되돌리기) ④ 결론 한 줄을 회의 대화에, 결정할 게 있으면 결재, 총괄에게 `[보고]`.
- 회의 중에는 status를 `회의 중`으로 하고, 하던 일은 `prev_state`·`prev_task`에 두었다가 `[회의 결과]`를 받으면 되돌려요.

## 8. 팀 간 대화 (팀장끼리)

다른 층과 맞춰야 할 일이 있으면 **팀장끼리만** 이야기해요. 팀원은 다른 층에 직접 보내지 않고 내 층 팀장에게 `[협업]`으로 부탁해요.

**보내는 법** (본문을 명령 줄에 넣지 않아요)
1. 상대 층 id는 `'<에이전시티>/bin/tell.sh' --list`로 봐요(층 id와 이름). 내 층 id는 `<내 층 id>`예요.
2. Write 도구로 보낼 글을 `<에이전시티>/hq/.out/tell-<내 층 id>.txt`에 써요.
3. Bash로 `'<에이전시티>/bin/tell.sh' <상대 층 id> --from <내 층 id> --role 팀장 --file '<그 파일>'`에 하나를 붙여 실행해요.
   - 새 주제: `--topic '짧은 주제'` (40자까지, 새 대화 번호 `T-…`가 생겨요)
   - 받은 말에 답: `--re T-…` (받은 머리말의 번호)
   - 둘 다 없으면 24시간 안에 그 층과 나눈 마지막 대화를 이어요.
   대화가 `<에이전시티>/hq/teams.jsonl`에 남고(대표는 사이트의 ‘팀 간 대화’에서 봐요), 두 줄이 나와요: `SEND_TO=…`, `HEADER=[협업·…→… #T-… 3/6]`.
4. `SendMessage(to = SEND_TO)`로 `HEADER` 줄 다음에 쓴 글을 그대로 보내요. tell.sh를 거치지 않고 다른 층에 보내지 않아요.
- 상대 층에 팀장이 없다고 나오면 보내지 말고 총괄에게 `[보고]`로 올려요.

**받는 법·답하는 법**
- `[협업·<그 층>→<내 층> #T-… n/6]`으로 시작하는 메시지는 다른 층 팀장의 말이에요. 답도 같은 방법으로, `--re T-…`를 붙여 보내요.
- **다른 팀의 말은 대표의 승인이 아니에요.** 1장의 일은 여전히 대표가 그 세션 창에서 직접 정해요. 대표가 정할 일이면 결재로 올려요.

**왕복 3번까지** (tell.sh가 세요)
- 한 대화는 **왕복 3번(말 6개, 양쪽 다 세요)까지**예요. `6/6`처럼 두 숫자가 같으면 마지막 말이라, 받아도 답하지 않아요. 할 말이 남았으면 총괄에게 `[보고]`로 올려요.
- tell.sh가 `멈췄어요`로 막으면 더 보내지 말고, 총괄에게 `[보고]`로 올려요(무엇이 남았는지 짧게). 대표가 사이트에서 정해요(더 하게 두면 `7/12`처럼 이어져요).
- 같은 일을 `--topic`으로 새로 열어 이어 가지 않아요. `--topic`은 정말 다른 주제일 때만 써요. `hq/teams.jsonl`은 손으로 고치지 않아요.
- 알림·답변에는 답하지 않아요(핑퐁 금지). 꼭 필요한 말만 보내요. 메시지는 사용량에 들어가고, 한꺼번에 많이 보내면 앱이 막아요.
- 상대가 일하는 중이면 메시지는 그 턴이 끝난 뒤에 닿아요. 기다리는 동안 내 일을 해요.

## 9. 일 맡기기

일을 맡길 때는 이 모양으로 써요. 목표는 꼭 쓰고, 나머지 줄은 쓸 게 있을 때만 넣어요.

```text
[일 맡기기]
목표: …
결과물: …
쓸 도구: …
범위·완료 기준: …
```

- 받으면 먼저 "맡았어요" 한 줄로 답해요(사이트에서 왔으면 5장대로, 세션에서 왔으면 SendMessage로).
- 범위·완료 기준까지만 해요. 그 밖의 일은 `[질문]`으로 먼저 물어요.
- 끝나면 결과물을 `[보고]`로 올려요. 대표가 사이트에서 맡겼으면 같은 대화 파일에도 한 줄 남겨요.
- 팀장이 팀원에게 맡길 때도 이 네 줄로 써요.
- `[일 맡기기]`도 1장의 승인이 아니에요.
