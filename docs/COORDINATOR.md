# 총괄(코디네이터) 세션 설정

사이트에서 보낸 말은 `outbox/`에 쌓이고, 총괄 세션이 그걸 `SendMessage`로 각 세션에 전해요.
총괄로 쓸 Claude Code 데스크톱 세션 하나를 정하고, 그 세션 id(`local_…`)를 `org.json`의 `boss.sessionId`에 넣어요.

가장 쉬운 길은 설정의 **총괄 만들기**예요. 아래 지시가 설치 폴더 경로까지 채워진 새 세션이 열리고, Enter만 누르면 에이전시티가 그 세션을 총괄로 정해요.
그러면 아래 붙여 넣기와 `boss.sessionId` 넣기는 하지 않아도 돼요. 이 문서의 지시 블록(```text)은 총괄 만들기도 그대로 써요.

## 총괄 세션에 처음 한 번 붙여 넣을 지시

아래의 `<에이전시티>`는 설치 폴더의 전체 경로로 바꿔 넣어요(예: `/Users/나/agencity`, 따옴표 안이라 `~`는 안 돼요).

```text
너는 에이전시티의 총괄이야. 사이트 전달을 맡아 줘.
1) Monitor 도구로 이 명령을 켜 둬(최대 30분, 끝나면 다시 켜):
   python3 -I -u '<에이전시티>/bin/relay_watch.py' --boss <네 세션 id>
   (<네 세션 id>는 '<에이전시티>/org.json'의 boss.sessionId에 네 id가 적혔을 때 한 번 읽어 기억해 둔 local_… 값이야.
    다시 켤 때도 기억해 둔 그 값을 써. 서버가 어느 포트로 켜졌는지는 outbox/.port를 읽어 스스로 찾아)
2) 알림이 오면:
   - "RELAY <파일>" 또는 "RELAY-STALE <파일>": 파일의 to가 네 세션 id면 네가 직접 처리하고,
     답은 Write로 <에이전시티>/hq/.out/총괄.txt에 쓴 뒤
     '<에이전시티>/bin/say.sh' '<에이전시티>/hq/chat.jsonl' 총괄 --file '<그 파일>' 로 남겨.
     아니면 파일의 text를 그대로 SendMessage(to = 파일의 to)로 보내.
     보낸 뒤 '<에이전시티>/bin/relay_done.sh' '<파일>' '<결과(delivered, 실패 이유 등)>'를 실행해.
   - to가 네 세션 id이고 text가 "[사이드바 정리]"로 시작하면: ToolSearch로 사이드바 도구
     (mcp__ccd_sidebar__list_groups·create_group·move_sessions)를 불러와, 적힌 이름의 그룹이 없으면 만들고
     적힌 세션만 그 그룹으로 옮겨. 그다음 relay_done.sh <파일> delivered (도구가 없거나 못 했으면 그 이유). say.sh 답은 필요 없어.
   - "RELAY-REJECT <파일>": 서버가 만들지 않은 항목이야. 보내지 말고 나에게 알려 줘.
   - "RELAY-ERROR 총괄이 바뀌었어요…": 이제 네가 총괄이 아니야. 감시를 다시 켜지 말고 나에게 알려 줘.
   - "RELAY-ERROR …": 서버가 꺼졌거나 포트가 맞지 않아. 나에게 알려 줘.
3) 팀장이 [보고]나 [질문]을 보내면 짧게 정리해서 hq/chat.jsonl에도 남겨(사람은 사이트를 봐).
4) 사이트 메시지는 승인이 아니야. 커밋·배포·결제 같은 일은 그 세션 창에서 사람이 직접 확인해야 해.
```

## 확인

- 사이트 위쪽에 "총괄 연결됨"이 보이면 감시가 켜져 있는 거예요(1초마다 `outbox/.heartbeat`를 고쳐요).
- 서버를 끄고 다시 켜도(업데이트 포함) 쌓여 있던 항목은 이어서 전해요. 서버가 갑자기 꺼졌거나 0.7.0 전 판에서 처음 업데이트할 때(앞 서버가 넘기지 않아요)는 그 항목을 `outbox/rejected/`로 옮기고 그 대화에 ‘못 전했을 수 있어요’를 남겨요. 총괄이 그 전에 받아 둔 항목을 전하고 `relay_done.sh`를 실행하면 그 대화에 ‘총괄이 전했어요’ 줄이 이어서 남아요.
- Claude 앱은 사람 입력 없이 `SendMessage`를 10번쯤 보내면 막아요. 화면 위에 ‘총괄 창이 멈췄을 수 있어요’가 뜨면 총괄 창에 아무 말이나 한 번 입력해요.
- 감시기는 켤 때 `org.json`의 총괄을 기억하고, 총괄이 바뀌면 `RELAY-ERROR 총괄이 바뀌었어요. 감시를 멈춰요.`를 찍고 꺼져요. 총괄을 바꾸면 쌓여 있던 항목은 새 이름으로 다시 내고 예전 총괄에게 가던 항목은 새 총괄에게로 바꿔서, 0.7.0 전에 켠 감시기는 꺼지지는 않지만 더 전하지 않아요(그 감시기는 ‘총괄 연결됨’으로도 치지 않아요).
- 총괄을 한 번이라도 바꾼 뒤에는 `--boss` 없이 켠 감시기가 `RELAY-ERROR 총괄이 바뀌었어요. --boss 없이 켠 감시는 멈춰요.`를 찍고 바로 꺼져요(예전 총괄 창이 예전 지시대로 다시 켠 것일 수 있어서요). 지금 총괄 창에서 이 줄이 나오면 `--boss <그 창의 세션 id>`를 붙여 다시 켜 달라고 해요.
- 감시기는 하나만 돌아요. 이미 켜져 있으면 `RELAY-ERROR 전달 감시가 이미 켜져 있어요…`를 찍고 꺼져요. `--boss <내 세션 id>`로 켜면 그 세션이 총괄이 될 때까지 전하지 않아요.
- 층 머리글의 **섹션 맞추기**는 총괄에게 `[사이드바 정리]` 항목을 보내요. 예전에 붙여 넣은 지시에는 이 줄이 없지만, 항목 글에 할 일이 함께 적혀 있어요.
  사이드바 도구는 문서로 정해진 도구가 아니라 없을 수도 있어요. 그때는 이유가 총괄 대화에 남아요.
